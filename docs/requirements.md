# Requirements

**English** · [Español](requirements.es.md)

Two different things need resources: the **installer** (a small web application) and the **installation it
generates** (HCL DX Compose and its prerequisites, on your cluster).

## To run the installer

| Way | What you need |
|---|---|
| Docker (your PC) | Docker or Podman. `docker run --rm -p 8080:8080 ghcr.io/europesip/hcl-dx-compose-installer:<version>` and a browser |
| Helm chart (a cluster) | Kubernetes or OpenShift, Helm 3.8+ (OCI charts), an Ingress or a route if it must be reachable from outside (keep `auth.enabled=true`) |
| Headless (Node) | Node.js 20.19 or later. No browser, no server: see [Headless mode](headless.md) |
| AWS options (optional) | An AWS access key with permission to create EC2 / EKS (and a Red Hat token for ROSA). Only used to create or delete that environment |

The installer is light: the chart requests 20m CPU and 96 MiB (limit 768 MiB, for the AWS jobs). Nothing it generates is sent to a server: see [Security](security.md).

## For the installation it generates

### Cluster

| | |
|---|---|
| **Kubernetes** | A cluster you can reach with `kubectl` as an administrator (it creates namespaces, CRDs for the prerequisites, Ingress resources). Tested on k3s and Amazon EKS; the scripts also support OpenShift (creating a ROSA cluster from the installer is not yet tested end to end). Or let the installer create one: k3s on your PC (WSL2), on a Linux machine or on AWS EC2 |
| **Storage** | A `ReadWriteOnce` storage class and a `ReadWriteMany` one (DAM and other shared volumes). Defaults `dx-deploy-rwo` / `dx-deploy-rwx`; Longhorn, EBS + EFS... |
| **Ingress** | Traefik (k3s default), ingress-nginx or another class; on OpenShift, routes |
| **DNS and TLS** | A host name for the portal that resolves to the Ingress (`nip.io` works for a PoC). Your certificate, or a self-signed one generated by the scripts |
| **Existing CloudNativePG** | The PostgreSQL step installs its own CloudNativePG operator. In a cluster that already runs one, do not run that step until [#24](https://github.com/europesip/hcl-dx-compose-installer/issues/24) is done |

### CPU and memory

Kubernetes *requests* measured on the lab cluster (DX Compose CF239). The installer shows the estimate for your choice,
and RUNBOOK.md repeats it.

| What | CPU | Memory |
|---|---|---|
| HCL software only (DX Compose; + IQ, + Search) | ~8 | ~14 GiB |
| Everything (HCL + prerequisites + extras) | ~9.3 requested | ~20.6 GiB requested |
| Recommended free capacity for everything | ~13 | ~27 GiB |

### Tools on the machine that runs the folder

| Tool | Why |
|---|---|
| `kubectl` | Every step |
| `helm` 3 or 4 | The charts (the scripts adapt the Helm 4 flags when they find Helm 3) |
| `openssl`, `curl` | Certificates, checks of each step |
| `python3` | Collecting support data (`--collect`) and some checks |
| `sops`, `age` | Only for the webinar with SOPS-encrypted secrets |

Linux, macOS or Windows with WSL2. The scripts check the tools before they start.

### Accounts and files

| | |
|---|---|
| **HCL Harbor** (`hclcr.io`) | Your HCL account e-mail and its CLI secret, to pull the HCL charts and images. Or your own registry with a copy of them |
| **HCL DXClient licence** | Accepted in the wizard when the Script Application operator or ÓRBITA are installed |
| **`setup-postgres-dx.sql`** | HCL's script for the Web Engine on PostgreSQL (stage 3), copied into `lab-bbdd/` |
| **AI provider** (stage 4) | An OpenRouter API key, AWS Bedrock (key and region) or an Anthropic API key, for LiteLLM |

### Security note

Without the OpenBao option, the generated folder holds passwords and keys: keep it private. In the
[headless mode](headless.md) the secrets are separated in `secrets.env` and the secret files, so the rest can go to Git.
